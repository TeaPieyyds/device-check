# 设备体检（Device Check）

一个**只读、本地、不联网**的安卓应用安全自查小工具。

> 不杀毒、不下结论、不上传数据。它只负责把手机上装了什么，**用你看得懂的话讲清楚**。

---

## 🚀 快速开始（3 步，新手看这里）

第一次用？**跟着下面 3 步走就行**，不需要懂技术。

### 第 1 步：下载 APK

**点下面这个链接直接下载**（手机浏览器打开即可）：

👉 [**点我下载 app-release.apk**](https://github.com/TeaPieyyds/device-check/releases/latest)

> 📍 打不开或找不到？看 [**图文下载说明**](#-不会下载看这里)。

### 第 2 步：装 Shizuku（本工具的"权限来源"）

本工具需要 Shizuku 才能读取完整的系统信息（**它不是 Root，不会改系统**）。

1. 下载并安装 Shizuku：[**Shizuku 官方下载**](https://github.com/RikkaApps/Shizuku/releases)
2. 打开 Shizuku，**按它 App 里的提示启动服务**
   - 手上没电脑？用**无线调试**方式（Shizuku 里有教程）
   - 有电脑？用 adb 方式更简单
3. 看到 Shizuku 显示 **"服务已启动"** 就 OK

> 🎥 看不懂？B站搜 "Shizuku 教程" 有大量视频。
> ⚠️ **Shizuku 重启手机后需要重新启动一次**，这是正常的。

### 第 3 步：开始扫描

1. 打开 **设备体检**
2. Shizuku 会弹**授权请求** → 点 **允许**
3. 点 **「开始扫描」** → 等十几秒
4. 看结果：
   - 🟢 **绿色** = 认识，正常
   - 🟡 **黄色** = 不认识，你自己判断（可以点「分享给 AI」问问）
   - 🔴 **红色** = 可疑 / 是陌生的设备管理员，**重点看**

## ❓ 装上后不会用？看这里

| 你想干嘛 | 怎么做 |
|---|---|
| **看手机里都装了什么** | 打开 App，点「开始扫描」 |
| **这个应用安全吗？** | 绿色=认识；黄色=不认识（可点「分享给 AI」问豆包/DeepSeek） |
| **想卸载某个可疑应用** | 点该应用的「删除」按钮**连点 3 次** → 会跳到系统卸载页 |
| **日志看不懂** | 点右上角「人话 / 原样」切换，选「人话」 |
| **提示 Shizuku 未运行** | 去打开 Shizuku App，启动服务，再回来 |
| **扫描按钮点不动** | 多半是 Shizuku 没授权，看 App 内弹窗提示 |

> ⚠️ **再次强调**：本应用**不替你卸载任何东西**，只负责"告诉你有什么"。卸载与否你自己定。

## 它要解决什么问题

网上流传的"某某病毒伪装成系统服务、无法卸载、窃取隐私"之类的恐吓信息，
往往让普通用户陷于恐慌，进而做出**破坏性操作**（误删系统应用、盲目恢复出厂、把密码交到钓鱼页面）。

本工具的思路完全不同：

- **只呈现事实**：把真实的应用列表、权限、设备管理员、无障碍服务、开机自启列给你看
- **不制造恐慌**：命中白名单的给出人话解释；不认识的，**老实说"我不认识"**
- **把判断权交出去**：不认识的项，一键分享给 AI（豆包 / DeepSeek 等）或亲自打开看看
- **操作防手滑**：删除按钮要连点 3 次、安全要连点 2 次，且两个按钮左右分离

## 功能

| 功能 | 说明 |
|---|---|
| 应用清单 | 读取全部应用（含系统应用） |
| 白名单识别 | 系统包 / 厂商包 / 主流应用，命中即给中文解释 |
| 未识别项 | 提供【分享给 AI】【打开看看】两个出口 |
| 用户判定 | 【安全】(2 连击，标记后从列表移出) / 【删除】(3 连击，跳转系统卸载页) |
| 执行日志 | 底部实时日志，右上角一键切换 **人话 / 原样** 两种视角 |
| 多线程扫描 | 各项检查并行执行，互不等待 |
| 关于页 | 左上角 `ⓘ` 入口，说明能力边界与许可协议 |
| Shizuku 引导 | 未安装 / 未启动时弹窗引导，附官方下载与教程 |

### 关于「删除」按钮

它**不直接卸载任何东西**，只是帮你打开系统的卸载页面：

1. **优先**：用 **Shizuku 的 shell 身份** 执行
   `am start -a android.intent.action.DELETE -d package:<包名>`
   —— 因为 shell 拥有 `DELETE_PACKAGES` 权限，可以**绕开厂商对第三方 App 的拦截**
   （ColorOS / OriginOS 等 ROM 会拦截普通 App 发起的卸载 Intent，
   表现为「跳一下又回来」）
2. **降级**：若 Shizuku 不可用或执行失败 → 普通 `ACTION_DELETE`
3. **再降级**：跳转「应用信息页」，你在那里也能点卸载
4. **兜底**：都不行时明确提示「请到系统设置里手动卸载」，绝不静默失败

> 是否卸载，最终由**你在系统页面上**决定，本应用不代劳。

## 设计原则

1. **只读**。本应用**不执行任何删除、卸载、修改操作**。删除按钮只跳转系统卸载页（或降级到应用信息页），处置与否由系统和你决定。
2. **不联网**。所有检查在本地完成，不上传任何数据。（`INTERNET` 权限仅用于系统分享面板。）
3. **不猜测**。不认识的就说"不认识"，不编造"疑似病毒"之类的模糊判断。
4. **防误触**。高风险操作需要多次点击，且按钮间距最大化。

## 技术栈

- Kotlin + 传统 View（XML 布局），**刻意不用 Compose**，以保持极小体积
- [Shizuku](https://shizuku.rikka.app/) 提供无 Root 的 shell 能力
- 无任何第三方运行时依赖（Shizuku 与 androidx 之外）
- Release 开启 R8 混淆 + 资源压缩

## 构建

### 本地构建

```bash
./gradlew :app:assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

### 本地构建签名版

在项目根目录新建 `keystore.properties`（**已在 .gitignore 中，不会提交**）：

```properties
storeFile=/绝对路径/your.jks
storePassword=你的库密码
keyAlias=你的别名
keyPassword=你的密钥密码
```

然后：

```bash
./gradlew :app:assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`

### GitHub Actions（本仓库使用的方式）

推送到 `main` 分支后自动构建 Debug + Release 两个 APK。

Release 签名所需的 keystore 通过 **GitHub Secrets** 注入，不会进入代码库：

| Secret 名称 | 内容 |
|---|---|
| `KEYSTORE_BASE64` | keystore 文件的 base64 编码 |
| `KEYSTORE_PASSWORD` | 库密码 |
| `KEY_ALIAS` | 密钥别名 |
| `KEY_PASSWORD` | 密钥密码 |

> 生成 base64：`base64 -w 0 your.jks`
> **切勿**把 keystore 或密码直接提交到仓库。
